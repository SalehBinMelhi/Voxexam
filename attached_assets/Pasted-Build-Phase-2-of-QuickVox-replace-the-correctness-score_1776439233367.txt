=== BACKEND ===

1. Add two new nullable columns to the submissions table in 
   shared/schema.ts:
   - quickvoxInsight: text, nullable
   - quickvoxFollowUp: text, nullable
   Update insertSubmissionSchema accordingly.

2. Run `npm run db:push` (or `npx drizzle-kit push`) to sync the 
   database schema. Confirm both columns exist before proceeding.

3. In server/storage.ts, add a NEW function called 
   `evaluateQuickVoxAnswer(question: string, transcript: string)` 
   that:
   - Uses model "gpt-4o" (NOT gpt-4o-mini)
   - max_tokens around 250
   - temperature 0.7
   - Uses response_format JSON mode
   - Returns { insight: string, followUp: string }
   
   System prompt (use exactly this):
   
   "You are a perceptive listener responding to a spoken answer. 
   This is not an exam — there is no right or wrong answer. Your 
   job is to make the speaker feel heard and a little delighted 
   by what you noticed in their words.
   
   Return JSON with two fields:
   - insight: 1-2 sentences. A warm, curious observation about 
     what they said. Pick the tone (playful, thoughtful, 
     appreciative, or analytical) based on what fits their 
     answer. Never judge, never score.
   - followUp: one short question that builds on something 
     specific they said — not a new unrelated question. Make it 
     feel like a real conversation continuing.
   
   IMPORTANT: Respond in the same language as the answer. If the 
   answer is in Arabic, respond in Arabic. If in English, respond 
   in English. Match their language exactly."

4. In the submission grading path, branch on exam.mode:
   - If exam.mode === 'quickvox': call evaluateQuickVoxAnswer, 
     store result in quickvoxInsight and quickvoxFollowUp columns. 
     Leave correctness/understanding scores as null.
   - Else: keep the existing evaluateWithAI behavior untouched.
